Vibe Coding: Is There Validation Between the LLM and the Sink?

Vibe coding is exactly where unvalidated sinks ship. On October 21, 2026, CVE-2026-114107 was disclosed for HKUDS Vibe-Trading: a prompt injection that escalated to a root shell, rated CVSS 8.7. The advisory names the root cause in one sentence — an LLM-callable tool primitive shipped with zero input validation between the LLM and the sink. The short answer: a sink gap exists when model-controlled text can reach a shell, SQL query, file write or outbound request with nothing constraining it in between. What is an execution sink in vibe coding?

An execution sink is the place where data becomes action: a shell command, a SQL query, a file write or an outbound request. In vibe coding workflows the model often writes both the tool and its inputs, so an unvalidated sink turns any prompt injection into direct code execution on your machine.

The CVE-2026-114107 pattern: document to root shell

The Vibe-Trading chain, as described in the advisory, has five links — and only one of them needed to break:

1. A document carrying hidden instructions is loaded as context
2. Prompt injection: the document steers the model
3. The model emits a command as a tool argument
4. The tool passes the argument to the sink unvalidated
5. The sink executes it — with the agent's privileges, up to a root shell

Links 1 to 3 are hard to eliminate: models read untrusted documents, and models can be steered. Link 4 is entirely in the tool author's control. A single allowlist check, a full-string match, or an argument array instead of shell=True breaks the chain at the cheapest possible point. The advisory's lesson generalises to every agent framework: audit the gap between the LLM and the sink, not just the prompt.

      How to fix a sink gap

      • Prefer allowlists. Enumerate the legitimate values — actions, hosts, filenames — and reject everything else. Validation must reject 100% of values outside the allowlist, not just the attacks you have already seen.
      • Never build shell strings. Pass an argument array to subprocess without shell=True; where a string is unavoidable, quote with shlex.quote.
      • Parameterise SQL. Placeholders and bound parameters, never f-strings or percent formatting into execute.
      • Constrain types and shapes. isinstance and length guards plus a re.fullmatch pattern for free-text fields, checked before the sink — not after.
      • Pin outbound requests. Build request URLs from a fixed host allowlist instead of passing a model-supplied URL straight to requests.

      Frequently asked questions

      What is an execution sink?

      An execution sink is the point where data stops being text and becomes action: a shell command runs, a SQL query executes, a file is written, or a request leaves for a URL. If model output can reach that point unchanged, whoever controls the model's input effectively controls the action the sink performs.

      Why do allowlists beat blocklists for LLM tool inputs?

      A blocklist tries to name everything dangerous, and attackers only need one spelling, encoding or separator you forgot. An allowlist names the small set of values that are legitimate — three actions, five filenames, one URL host — and rejects everything else by default, including attack shapes nobody has invented yet.

      What validation actually counts between the LLM and a sink?

      Validation counts when it constrains the value before the sink sees it: membership in an allowlist, a full-string regex match, a strict type and length check, parameterised SQL instead of string formatting, or shell quoting plus an argument array instead of shell=True. A comment saying the input is trusted does not count.

      How is validation different from a sandbox?

      A sandbox limits the damage after a bad command runs: fewer permissions, no network, an isolated filesystem. Validation stops the bad command from being constructed at all. Sandboxes fail open when they are misconfigured or escaped; validated inputs never become commands in the first place. Serious setups use both layers together.
