Cybersecurity news today: what the 15,465-server scan means

MCP is the Model Context Protocol — the open standard connecting AI models and agents to tools and data. OX Security’s report, published via The Hacker News on October 6, 2026 and widely covered on October 18, 2026, looked at what people actually run: 15,465 public MCP servers across five registries, 5,095 unique hostnames — and found no vetting anywhere. 15.6% of hostnames resolved to infrastructure outside the US, including China and Russia. 2.3% of hostnames failed to resolve, including six unregistered domains available for about $4 a year — ready-made takeover targets. And about 0.45% sat on home networks or consumer tunnels: the smart-home experiment that quietly became a public server.

What is an MCP server?

An MCP server is a program that exposes tools — file access, APIs, smart-home controls — to an AI agent through the Model Context Protocol. Think of it as a USB-C port for AI: one standard plug between a model and everything it can touch. Developers run them locally for coding and home automation, but many end up reachable over the network — which is where the trouble starts.

The “by design” flaw underneath

The exposure problem sits on top of an architectural one. Anthropic’s official MCP SDKs for Python, TypeScript, Java and Rust use a transport called STDIO that accepts a “command” parameter and executes it verbatim — no sanitization. When OX Security flagged this as a systemic command-injection vulnerability, Anthropic confirmed the behavior is by design and declined to make protocol-level changes, pushing the entire burden of sanitization onto developers. Separately, OX Security’s earlier supply-chain advisory estimated roughly 200,000 vulnerable MCP server instances globally, with more than 150 million SDK downloads. A protocol that trusts its inputs, running on servers nobody vets, some of them in living rooms — that is the jungle.

How a home server ends up public

  • The forgotten tunnel. ngrok for remote access during a trip — still running months later, with a public URL.
  • The VPS with no auth. Moved the server off the laptop for reliability, skipped authentication “temporarily.”
  • The helpful default. Some setups bind to all interfaces instead of localhost — one config line between local and global.
  • The marketplace install. Community MCP servers install in one click, with no security review — and remote ones can run code that differs from their public repo.

How does an MCP server end up exposed on the internet?

The usual path: someone runs an MCP server at home for a smart-home or coding setup, then opens a public tunnel (ngrok, Cloudflare Tunnel) for remote access and forgets it — or deploys it to a VPS with no authentication. OX Security’s scan found these home and tunnel-exposed servers indexed publicly, reachable by anyone.

What is ngrok and why is it risky for MCP servers?

Ngrok is a tunneling service that gives a local program a public URL — handy for testing, dangerous when forgotten. A forgotten ngrok tunnel turns a local MCP server into a public one. OX Security found home MCP servers exposed specifically through consumer tunneling services like ngrok.

How do I secure a home MCP server?

Keep it off the public internet: bind to localhost or your LAN, put remote access behind a VPN, require authentication on every endpoint, prefer local STDIO transport over networked transports, close tunnels you don’t need, update the server software, and give each tool only the permissions it needs.
