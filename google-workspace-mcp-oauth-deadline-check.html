Am I affected? — 3-question check

1. Does an AI agent (yours, or one you operate) call Google Workspace — Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat or People — through MCP?

2. Does the same OAuth client serve both human users (REST APIs) and agent workflows (MCP)?

3. Have you already ticked "Use this client for an AI-powered agent" on the agent's OAuth client?

The 3-step fix (about 2 minutes)

  1. Open the Google Cloud console → Google Auth Platform → Clients. If one OAuth client serves both humans and your agent, create a separate OAuth client for the agent first — Google requires separate Client IDs for human vs. agent traffic.
  2. Select the agent's OAuth client and tick "Use this client for an AI-powered agent". Marking a client as agentic does not grant extra scopes or bypass user consent — it only lets Workspace MCP servers accept the traffic and lets admins apply agent-specific controls.
  3. Save, then verify: point a test MCP call (e.g. gmailmcp.googleapis.com) at the flagged client and confirm it connects. Do this before Nov 11 — on Nov 12 the flag locks permanently on existing clients.

The Nov 12 lock-in trap

This is the part most teams will miss. The toggle has been editable since October 12, 2026. Enforcement starts November 11. But on November 12, the agentic setting becomes permanent on existing clients — you can no longer flip it. An unflagged client is stuck non-agentic forever: to use Workspace MCP after that date you must mint a brand-new OAuth Client ID, mark it agentic, and update every config that referenced the old one (think mcp_config.json files scattered across machines). The cheap fix is ticking the box now; the expensive fix is a client-ID migration under pressure.

Who is NOT affected

Apps and integrations that only call Google Workspace REST APIs — classic Gmail/Drive/Calendar API integrations with no agent and no MCP — are untouched by this change. The requirement applies only to OAuth clients calling the Workspace MCP servers (Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat, People MCP endpoints).

What happens on November 11, 2026 to Google Workspace MCP?

Google Workspace MCP servers (Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat, People) start rejecting requests from any OAuth client not marked as agentic. The toggle lives in Google Cloud console → Google Auth Platform → Clients → "Use this client for an AI-powered agent".

What happens if I miss the November 11 deadline?

On November 12, 2026 the agentic setting locks permanently on existing OAuth clients. If yours isn't flagged, you can't flip it later — you must create a brand-new OAuth Client ID, mark it agentic, and update every config referencing the old client.

Are non-agent apps affected?

No. Apps that only call Google Workspace REST APIs are not affected — the requirement applies only to OAuth clients calling the Workspace MCP servers.

Can one OAuth client serve both humans and an AI agent?

Google says to keep them separate: one Client ID for human-interactive traffic (REST APIs), another for agent workflows (MCP). Mark only the agent's client as agentic. The flag grants no extra scopes and doesn't bypass user consent.

Google Cloud console → Google Auth Platform → Clients → select your OAuth client → check "Use this client for an AI-powered agent". Editable since October 12, 2026.
