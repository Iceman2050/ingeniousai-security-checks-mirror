Should you trust a shared script memory for your AI agents?

A developer just announced HomeLibrary — a shared memory so your AI agents reuse tested scripts instead of rewriting them (and reintroducing bugs) every time. The open-source MCP server behind it, HomeShed, is real — I cloned the repo and reviewed the code. But HomeLibrary itself isn't released yet. Here is the honest evaluator's take: what's verified, what's aspirational, and whether it fits you.

VERIFIED What the code review confirmed

  • The repo is real and substantial. github.com/keefng8/homeshed-mcp — a self-hosted MCP server (Claude Code, Claude Desktop, Cursor, VS Code, OpenCode) with 136 tools: cross-session memory, a known-bugs list (“seen this error before?”), a logic solver, git, Docker, Proxmox monitoring, and secret-leak scanning of your AI transcripts.
  • Free and open source (Apache-2.0). One install, no account. Note honestly: a paid HomeShed Pro add-on also exists — the core is free, the ecosystem has a commercial tier.
  • Security defaults are genuinely thoughtful. Token auth on every request, binds to localhost only, tools that act on your machines start switched off, per-client keys with rate limits, secrets in a Fernet-encrypted vault, SSRF guards, and rule packs that vet commands before the agent runs them. A published SECURITY.md with a private disclosure process. No hardcoded live secrets found in the code.
  • Actively built, not abandoned. Created Oct 9, 2026; 7 releases in 7 days (v0.3.2 latest); 138 test files; maintained changelog. The token-savings tracker the author cites (system.savings, added in v0.3.2) exists in the code.
  • The “second opinion” hook exists. The author's “Shedkeeper” shadow-mode concept appears in the codebase as an optional companion-service integration — the code comments note the public copy ships without it, matching the author's “my local setup” framing.

UNRELEASED UNVERIFIABLE What's not proven yet

  • HomeLibrary itself doesn't exist yet. The name appears zero times in the repository — no code, no branch, no release. The author says it's in development and being tweaked before any release. Every specific feature claim (Sure/Likely/Weak match scoring, “Missed Requests” log, duplicate/stale/failing entry flags, “never stores secrets”, passkey phone-tap approval) is the author's description of unreleased software. Treat it as a roadmap, not a product.
  • The savings figure is one person's anecdote. “~7.9k tokens / £0.28 this week” comes from the author's own screenshot — plausible, but not independently verifiable, and your mileage will differ entirely with your workload.
  • Tiny, brand-new community. 8 stars, 4 forks, one maintainer, 7 days old. The engineering looks professional, but nothing here is battle-tested at scale. Adopt with the caution you'd give any week-old infrastructure dependency.
  • The core security tradeoff is yours to manage. A shared script memory means agents execute shared code. An allowlist plus your explicit approval per run is the right shape — but a poisoned, stale, or subtly buggy shared entry propagates to every agent that reuses it. The safety of the system equals the rigor of your review process.

The 60-second fit check — is this for you?

The bottom line

HomeShed: real, open, and unusually well-engineered for its age — worth a star and a test drive if you live in AI coding agents. HomeLibrary: an exciting announcement of software that doesn't exist yet — judge it when there's code, not screenshots. And whichever shared-memory tool you eventually use, remember the iron rule: a shared script library is only as safe as the review process guarding what goes into it.
