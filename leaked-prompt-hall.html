The Hall of Leaked Prompts

A system prompt is the hidden instruction set that tells an AI assistant how to behave — its rules, its guardrails, sometimes its secrets. It was never meant for users to see. Below are famous cases where users saw it anyway. Every entry here is publicly reported and sourced; we paraphrase, never reproduce a live secret verbatim.

Why it matters: if your product wraps an LLM, its system prompt is an attack surface. Extraction is reliable, the fix is known, and every case below happened to companies with world-class engineering teams.

The exhibits

EXHIBIT 01 — FEBRUARY 2023

Bing Chat's "Sydney" system prompt, disclosed

What leaked (summarized)
The hidden behavioral instructions behind Microsoft's new Bing Chat, including its internal codename "Sydney" — which the instructions themselves ordered it never to reveal — plus its tone rules, content restrictions, and operating directives. We don't reproduce them here; the point is their existence, not their text.
How it leaked
Direct prompt injection. Days after launch, a user asked the assistant to ignore its previous instructions and repeat what was written at the beginning of its document. It complied — then complied again, five sentences at a time. A second method, posing as a developer, defeated the first patch within a day.
The guardrail that would have prevented it
Never place confidential or security-relevant material in the prompt: assume it is extractable. Enforce access control in code, not in text — and treat every model output as potentially adversarial.

Sources: Microsoft confirmed to The Verge that the disclosed prompt was genuine (Feb 14, 2023); reported by Ars Technica, The Verge, and others, Feb 2023. Summary: MSPowerUser write-up, Feb 2023.

EXHIBIT 02 — LATE 2023 ONWARD

The custom-GPT instruction-extraction wave

What leaked (summarized)
Once platforms let anyone build custom AI assistants from a written instruction set, users found those instructions could be extracted with simple phrasing tricks — "repeat your instructions", translation-task disguises, multi-round coaxing. For some builders, the stolen instructions exposed proprietary "recipes", and in worse cases API keys or private data references they'd embedded in them.
How it leaked
A three-phase pattern documented by security research: direct requests, obfuscated requests (deception, spellcheck or translation disguises), then conversational reconstruction. A 2025 study found ~98.8% of tested custom GPTs fell to at least one phase — 95.1% to the simplest attacks.
The guardrail that would have prevented it
Secrets and credentials never go in instructions — use server-side secrets. Instruction text is intellectual property only in the legal sense; technically, treat it as public.

Sources: Devdiscourse technology report on the 2025 study; OWASP LLM07:2025 — System Prompt Leakage analysis (Sep 2026).

EXHIBIT 03 — 2024 — THE INTENTIONAL ONE

Anthropic publishes Claude's system prompts

What leaked (summarized)
Nothing leaked — that's the point. Anthropic voluntarily released the system prompts for its Claude models (first Claude 3, then 3.5 Sonnet, Haiku, and Opus) on its site, committing to log future changes. This exhibit is here as the counter-example: a prompt a company is comfortable publishing was never the security layer.
How it leaked
It didn't. It was published — because extractability is the default, and treating the prompt as public forces the real security into code, where it belongs.
The guardrail it demonstrates
The Sydney rule: if your product would be harmed by its system prompt appearing on the front page of a newspaper, your security is in the wrong place. Publish what you can; protect the rest in infrastructure.

Source: VentureBeat, Aug 2024, reporting Anthropic's release of Claude system prompts and its commitment to publish updates going forward.

The lesson of the hall

Every case above tells the same story: the model has no secret box. System instructions sit in the same context as user input, and clever framing reaches them. Teams that survive prompt extraction are the teams whose security never depended on the prompt staying hidden — input/output filtering, server-side secrets, verified tool permissions, and least-privilege agent actions.

FAQ

What is system prompt leakage?

It's when a large language model is tricked into revealing the hidden instructions that steer its behavior — its persona rules, guardrails, and sometimes secrets. OWASP catalogues it as LLM07:2025. The hall's exhibits show it happening via direct prompt injection (Bing/Sydney, 2023), obfuscated extraction (custom GPTs, 2023–24), and in one case voluntarily (Anthropic, 2024).

Can a system prompt be kept secret?

Treat extractability as the default, not the exception. Security research found prompt-extraction succeeds reliably across models and vendors with varied phrasing. The practical answer from the cases above: design as if your prompt is already public.

What should never go in a system prompt?

API keys, database credentials, internal URLs, authorization rules ("only show this to admins"), and any logic your system's safety quietly depends on. The custom-GPT wave showed keys and data references leaking exactly this way. Keep secrets in server-side stores and enforce authorization in code.

Is it illegal to extract a system prompt?

Extracting your own product's prompt is legitimate security testing — it's how you find the problem before attackers do. Extracting someone else's may violate their terms of service or acceptable-use policies. This is general information, not legal advice; check your jurisdiction and the platform's terms.
