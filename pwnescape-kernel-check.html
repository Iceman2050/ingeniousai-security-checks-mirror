CVE-2026-99999 “PWNESCAPE” — CVSS 9.3 CRITICAL — OCT 2026

Can a virtual machine read your host's memory?

A researcher just proved it: PwnEscape, a flaw in the Linux kernel's networking code, lets specially crafted packets sent from inside a guest VM read the host computer's memory — about 32 bytes per packet, for as long as the attacker keeps sending. In lab conditions the same flaw crashed the host with two packets and broke out to administrator control. It was demonstrated against Vercel's live production sandboxes, and Vercel confirmed it. If you're exposed, do this now

  • Update the HOST kernel to a fixed version (or your vendor's build containing the fix) and reboot into it. Updating only guests changes nothing.
  • There is no workaround if you can't patch yet — but you can narrow the blast radius the way Vercel does: keep host kernels current, disable nested virtualization, and run each microVM under a least-privilege jailer (Firecracker's jailer model).
  • Who's actually at risk: clouds and platforms running untrusted tenant code in VMs on shared hosts. A single-purpose server with no untrusted guests is far less exposed — the attack needs code execution inside a guest first, and no in-the-wild exploitation has been reported.

Why this one matters beyond one cloud

  • It's in the shared layer, not one vendor's setup: the bug is in the Linux kernel's networking code that the host runs — the same layer almost every large cloud uses to separate customers' workloads. Vercel's sandbox was reportedly hardened beyond industry standards with no misconfiguration found.
  • A new attack class: per the researchers, untrusted checksum metadata can rewrite security-sensitive packet fields after the kernel validated them — undermining assumptions across the networking stack, far beyond this one VM escape.
