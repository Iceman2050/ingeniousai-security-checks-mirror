FAQ — API deprecation

What is an API breaking change?

An API breaking change is any change that makes existing integrations fail or behave differently — a retired endpoint, a renamed field, a shut-down model, or a repriced plan. Deprecation is the warning; the breaking change is what lands at sunset. Every entry on this page's wheel is a real one, with its source linked.

What is the difference between API deprecation and API sunset?

Deprecation is the warning: the vendor marks an endpoint, model, or API version as going away while it still works. Sunset is the final shutdown date — the endpoint or version stops being served. Twilio's Programmable Video end-of-life announcement and Amazon Pinpoint's October 30, 2026 end of support are both sunsets.

How much notice do vendors give before API breaking changes?

It varies wildly: OpenAI's policy aims for at least six months on generally available models (but shipped a three-month notice in October 2026), Anthropic promises at least 60 days, Meta gave roughly 90 days for the Facebook Groups API, and X ended free API access with about a week's notice in February 2023. Never assume the default — read the actual policy.

How do I protect my code from API deprecation?
