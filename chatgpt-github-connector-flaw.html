What is the ChatGPT GitHub connector?

An integration that lets ChatGPT read and work with your GitHub repositories — convenient, and a new path for repo secrets to leak if misconfigured.

A researcher report published October 15, 2026 alleges that ChatGPT's GitHub connector could let attackers steal repository secrets through indirect prompt injection — triggered, the report claims, when a user asks ChatGPT to review an attacker-controlled public repo, with unauthorized writes and secret exfiltration allegedly happening without additional user confirmation. The researcher calculated CVSS 4.0 score 9.3 (Critical). Read the label carefully: alleged, not independently verified. But the pattern it describes — an AI holding your credentials while reading untrusted content — is real, and this 60-second checklist closes it either way. Free, no signup.

The 60-second connector-hardening check — tick what applies

Audit and revoke stale access today

# List everything authorized on your GitHub account/org # Settings → Applications → Authorized OAuth Apps (do this in the UI) # Then revoke anything AI-related you don't actively use. # For orgs, also check: Settings → Third-party Access gh auth refresh -h github.com -s read:org # least-privilege re-auth # Rotate any secret that was live during an untrusted review: gh secret list # inventory first gh secret delete DEPLOY_TOKEN && gh secret set DEPLOY_TOKEN # then rotate
  • Least privilege is the whole game: read-only scopes for review work; write scopes only where the AI genuinely needs to push — and never both at once on untrusted input.
  • Separate your sessions: one connected session for your own trusted repos; a fully disconnected session (no connectors, no secrets) for reviewing anything you didn't write.

What's alleged vs. what's real — stay honest

  • Alleged (unconfirmed): the specific ChatGPT GitHub connector flaw — the 9.3 CVSS, the secret-exfiltration chain, the no-confirmation writes. A single researcher report; not independently verified. We describe the claim, not the exploit, and we won't publish attack details.
  • Real: indirect prompt injection as an attack class — MITRE enshrined it as T1698 in ATT&CK v20 (Oct 2026); HackerOne saw a 540% rise in valid prompt-injection reports; 141 CVEs mention prompt injection, 87 of them in 2026 alone.
  • Real: the Copilot CLI "Cryptographic Context Injection" finding (Oct 2026) — an attacker-controlled webpage allegedly guiding a coding agent to read local files and exfiltrate them. Same pattern, different product: AI + credentials + untrusted content = exposure.
  • Bottom line: whether or not this one report pans out, every AI connector holding repo credentials deserves the checklist above. Harden the pattern, not just the headline.
