SHAI-HULUD NPM SUPPLY-CHAIN WAVE — OCT 2026

One npm install can silently steal every secret on your machine

The Shai-Hulud supply-chain wave turns trusted npm packages into credential thieves. Malicious package versions fire their payload from the package's install script — before your application code ever runs — and harvest npm tokens, GitHub tokens, AWS keys, Vault tokens, Kubernetes credentials, SSH keys, .env files and crypto wallets from developer machines and CI runners (per Socket's analysis). The latest wave hit the tensorlake AI SDK: version 0.5.144, published October 8, 2026, ran a preinstall hook executing an obfuscated loader (lib/setup.mjs) that launched the worm (lib/Math_Symbol.js) with the Bun runtime. Earlier waves pushed 84 malicious versions across 42 @tanstack/* packages in six minutes, and planted persistence hooks in .claude/settings.json so the malware survived package removal. How the attack works (per Socket, JFrog, Microsoft, Snyk and StepSecurity analyses):
• Attacker compromises a maintainer account or CI token, then publishes a poisoned version of a legitimate package.
• You run npm install → the package's preinstall/install/postinstall hook executes attacker code before any of your code runs.
• The payload scans your machine and CI environment for secrets: ~/.npmrc tokens, GitHub tokens, SSH keys, AWS/GCP credentials, cloud metadata endpoints, Vault, loose .env files.
• Stolen data is exfiltrated — sometimes via encrypted HTTPS, sometimes via public GitHub repos created on the victim's own account as the drop point.
• The worm self-propagates: stolen npm tokens are used to publish poisoned versions of every package the victim can publish.
• It persists: .claude/settings.json SessionStart hooks, .vscode/tasks.json backups, commits titled chore: update dependencies pushed to your repos with stolen GitHub tokens.

Red flags: what a poisoned package looks like

Obfuscated install scripts. The tensorlake payload shipped as an obfuscated loader (lib/setup.mjs) plus an ~856KB worm file (lib/Math_Symbol.js). Legitimate install scripts are readable; walls of encoded text are not.
Install hooks in packages that don't need them. A TypeScript SDK or caching library running preinstall network code is suspicious by construction.
Unexpected network calls during install. Install steps should not phone home, probe cloud metadata endpoints, or open encrypted connections.
New or changed maintainers. Waves began with compromised maintainer accounts and hijacked CI publish tokens — a familiar package with a brand-new publisher deserves scrutiny.
Hook files appearing in your repo. .claude/setup.mjs, new SessionStart entries in .claude/settings.json, or .vscode/tasks.json tasks you didn't write.
Public repos on your account you didn't create. The worm created public GitHub repositories on victims' accounts as exfiltration drop points — an unfamiliar repo is an infection indicator.

Frequently asked questions

What is the Shai-Hulud npm attack?

Shai-Hulud is a self-propagating npm supply-chain worm family. In documented waves — including May 2026 and a September/October 2026 wave — attackers published malicious versions of legitimate packages (e.g. tensorlake@0.5.144 on October 8, 2026). The payload fired from the package's install script during npm install, stole credentials from the machine, and used stolen npm tokens to republish poisoned versions of packages the victim could publish to. Analysts including Socket, JFrog, Microsoft, Snyk and StepSecurity have tracked the campaign.

What secrets does the Shai-Hulud worm steal?

Per Socket's analysis of the tensorlake compromise: npm tokens, GitHub tokens, AWS credentials and secrets, HashiCorp Vault tokens, Kubernetes credentials, SSH keys, .env files, cryptocurrency wallets and messaging-app data — anything accessible to the process running the install.

How did Shai-Hulud persist after the package was removed?

Researchers found the worm planted persistence outside node_modules: a SessionStart hook in .claude/settings.json pointing at a dropped .claude/setup.mjs script, a backup .vscode/tasks.json task that runs when the folder opens, and commits of those configs to reachable repositories via stolen GitHub tokens. Some variants also enrolled the host as a self-hosted GitHub Actions runner. Removing the malicious package alone did not remove these hooks.

How do I protect my project from malicious npm install scripts?

Run the 8-step self-audit above: review recent dependency updates, inspect package.json lifecycle scripts across the tree, read any install script before trusting it, check for planted hook files (.claude/settings.json, .vscode/tasks.json), review lockfile diffs, rotate secrets that were visible during installs, and going forward use lockfiles, npm's ignore-scripts option, and 2FA on your npm account.

Was my project affected if I installed a compromised package version?

Check exactly which versions you installed against the flagged versions (e.g. tensorlake@0.5.144) and when. If you installed a malicious version, assume any credential accessible during the install was exfiltrated — rotate npm tokens, GitHub tokens, cloud keys and everything in .env files — and inspect your repos for planted hook files and commits you did not make.
