Why do agent incidents surface in logs first?

Because agents act through legitimate channels at machine speed, so prevention sees authorized-looking traffic. The difference between a busy agent and a hijacked one is the pattern of its actions over time, and patterns only exist in the record. Whoever reads the log first understands the incident first.

Build a crossing-ready log practice

  1. Log actions, not just chats: every tool call and external action with actor, target, timestamp and outcome. Conversations alone cannot reconstruct a crossing.
  2. Make the four patterns findable: credential access, token operations, scope changes and wallet touches must be distinct event types, not lines in a debug stream.

  4. Rehearse the packet: pick one agent and one past week, and build the full timeline. Time it. That number is your real disclosure readiness.
  5. Keep retention boring: logs retained long enough to cover your slowest dispute, stored where an incident cannot quietly edit them.

Frequently asked questions

What is a boundary crossing in an agent log?

A boundary crossing is an action in an agent's log that falls outside the scope the agent was given: reaching for credentials it does not need, forging or replaying tokens, escaping its assigned tools or data, or touching a wallet. BoundaryVault hunts four declared patterns of this kind and presents each as a finding for human review.

It reads records after the fact. It does not monitor live agents or block actions.

What is LLMjacking?

LLMjacking is the theft of compute through a hijacked AI agent or stolen access: the attacker runs their workloads on the victim's accounts and keys. Symantec described an agent redirected this way in October 2026. The victim's clue is in the logs: actions and usage that do not match the agent's assigned work.

How is log forensics different from agent monitoring?

Monitoring watches live traffic and alerts while an incident unfolds. Log forensics works afterwards: it reconstructs what an agent did from the records that exist, which is what disclosures, disputes and insurance questions actually consume. The two complement each other; when prevention and monitoring miss, the log is the last evidence standing.

What should agent logs record to be forensically useful?

Record every tool call and external action with the acting agent, the target, a timestamp and the outcome. Make credential access, token operations, scope changes and wallet touches distinct event types. Retain the logs beyond your slowest dispute window, in storage an incident cannot quietly rewrite.
