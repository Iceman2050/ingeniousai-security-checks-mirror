The 8-question MCP-as-C2 exposure check

A “Yes” means the control is in place; a “No” is an opening for C2-style abuse.

1. Are your MCP server ports bound to localhost only, never exposed to the network?

2. Do you have egress controls (firewall / proxy) restricting what your MCP tool servers can reach?

3. Is every tool call logged centrally with timestamps, arguments, and the calling session?

4. Do you run anomaly detection (or at least periodic review) on tool-call patterns — odd hours, new destinations, repeated exec loops?

5. Are bearer tokens / auth secrets for local MCP services rotated and scoped, not hardcoded in scripts?

6. Is exec_in_session / shell-execution tooling disabled or gated behind approval on production agents?

7. Do you scan your own estate for internet-exposed MCP ports — the very thing the Gentlemen affiliate was scanning for?

8. Would your monitoring distinguish a criminal’s exec_in_session loop from normal agent traffic?

Why MCP makes such a good C2 channel

  • Execution is the product. MCP servers exist to run tools on command — exec_in_session is a feature. An attacker who reaches one doesn’t need to smuggle in malware; the execution primitive is already there.
  • It looks like AI traffic. Tool calls blend into the rising tide of legitimate agent activity. A script looping SSH checks through an MCP server looks like an agent doing its job — unless you specifically monitor for it.
  • Locally-bound is not safe-by-default. Azazel’s C2 ran against 127.0.0.1 — inside the victim environment. Perimeter firewalls never see it; only internal segmentation and egress controls do.
  • Exposed ports are a buffet. The internet-census-mcp-scanner fingerprint shows attackers scanning the whole internet for MCP ports as a general-purpose initial-access vector. Every exposed MCP server is a standing invitation.
  • It crossed from theory to operations. Tool poisoning and prompt injection were researcher demos; this was a ransomware affiliate running attack operations through MCP in a confirmed live campaign.

What this checker does NOT do

  • It does not scan your network or detect active C2 abuse — that needs traffic analysis and forensics.
  • It cannot tell you whether your fleet is already compromised.
  • It is informational, not a security audit. If you find an internet-exposed MCP port you don’t own, treat it as an incident.

Frequently asked questions

What are the CloudSEK Gentlemen Files?

“Caught in 4K: The Gentlemen Files” is a CloudSEK investigation published October 6, 2026. It documents Azazel, a Russian-speaking affiliate of the Gentlemen ransomware group, who compromised more than two dozen organizations and exfiltrated roughly 6TB of data. The investigation is notable for documenting the first confirmed operational use of MCP tooling as a command-and-control channel in a live criminal campaign.

How did the attacker use MCP as command-and-control?

Per CloudSEK: the operator’s va.py script — a ransom-note verification script — called a locally-bound MCP server at 127.0.0.1:35367 with a fixed bearer token to loop SSH verification checks across six internal hosts. Companion scripts (mcp_test.py, recon_mcp.py) showed this was developed, iterated tooling, not a one-off. The beacon log also showed internet-wide scanning under the fingerprint “internet-census-mcp-scanner,” hunting exposed MCP server ports as an initial-access vector.

Is this the first time MCP has been used as C2?

According to CloudSEK, the security research community had documented MCP attack risks since 2025 — tool poisoning, prompt injection, supply-chain abuse — but CloudSEK “has not identified prior public reporting of a threat actor operationally using MCP exec_in_session as a C2 channel in a live criminal campaign.” This investigation documents one confirmed instance.

How do I stop my MCP fleet from being abused as C2?

Bind MCP server ports to localhost only and never expose them to the network. Add egress controls on tool servers. Log every tool call centrally with timestamps, arguments, and sessions. Run anomaly detection on tool-call patterns. Rotate bearer tokens, gate shell-execution tooling behind approval, and scan your own estate for exposed MCP ports — the thing the Gentlemen affiliate was scanning for. What is the “internet-census-mcp-scanner” fingerprint?

Per CloudSEK, it is the beacon fingerprint from the Gentlemen affiliate’s tooling that scanned the internet at global scale hunting exposed MCP server ports — treating them as a general-purpose initial-access vector. If your threat-intel feeds or scan logs show that fingerprint, someone is probing for exactly the MCP servers this page helps you lock down.
