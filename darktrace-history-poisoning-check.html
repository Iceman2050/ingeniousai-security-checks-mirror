On September 24, 2026, Darktrace published "conversation history poisoning" research with a disturbing finding: Claude Code, Codex, Kiro-CLI, and Pi all store conversation history in plain local SQLite — with no integrity verification — and in testing, all four accepted fabricated history as genuine. In Darktrace's tests, the planted commands escalated to full Active Directory compromise. No network exploit needed: anything on your machine that can write a file can rewrite your agent's memory. Why this attack is so cheap

  • No exploit required. The attack is editing a file your own machine already has. No network access, no privilege escalation — just a write.
  • The agent does the escalation. Coding agents run with your privileges. A fabricated "you approved this" turn converts file-write access into whatever rights you have — including domain operations.
  • Memory is authority. Agents treat conversation history as the record of what was authorized. Poison the record, and the agent's authorization model works against you.
  • SQLite is unsigned by design here. The harnesses chose convenience — plain local SQLite — without adding signing or hash chains. Until vendors ship integrity verification, detection is your only defense.
  • Four for four. Claude Code, Codex, Kiro-CLI, and Pi all failed the same way. This is an industry pattern, not one vendor's bug.

Cybersecurity news: frequently asked questions

What is conversation history poisoning?

Conversation history poisoning is an attack where an attacker edits the stored conversation history of an AI coding agent — injecting fabricated turns the user never sent — and the agent accepts the forgery as its own memory, then acts on it. Darktrace's September 24, 2026 research showed that Claude Code, Codex, Kiro-CLI, and Pi all store history in plain local SQLite, and in testing the agents accepted fabricated history, which led to full Active Directory compromise.

Which AI coding agents are affected by history poisoning?

According to Darktrace's September 24, 2026 "conversation history poisoning" research, all four tested harnesses were affected: Claude Code, Codex, Kiro-CLI, and Pi. Each stores conversation history in plain local SQLite with no integrity verification, and each accepted fabricated history in testing.

How does conversation history poisoning lead to Active Directory compromise?

In Darktrace's testing, once the harness accepted fabricated history as genuine, the attacker could plant instructions inside fake "earlier" turns — commands the agent believed the user had authorized. Because coding agents run with the user's privileges, planted commands escalated through the environment to full Active Directory compromise. The poisoned memory becomes the authorization the agent never got from you.

How do I protect against conversation history poisoning?

Know where your harness stores history (plain local SQLite for the four tested agents); keep that directory writable only by you — no untrusted code, shared machines, or compromised repos should be able to touch it; verify conversation integrity before sensitive operations; treat any unexpected turn as hostile until proven otherwise; and keep your CLI harness updated, watching for integrity-verification features from the vendors.

Why do AI coding agents store history in plain SQLite?

Plain local SQLite is fast, simple, and works offline — engineering convenience, not a security decision. The problem Darktrace exposed is that nothing signs, hashes, or verifies those records, so any process with file access can rewrite the agent's memory and the agent cannot tell the difference.

Can an attacker poison history without network access to my machine?

Local file access is enough — no network needed. Any compromised dependency, malicious repo script, shared-machine user, or malware with file permissions on your home directory can edit the SQLite history file. The attack surface is "anything that can write to the history directory," which on most developer machines is a large set.
