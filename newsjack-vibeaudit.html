AI-GENERATED CODE — SHIPS WITH SECRETS

Grep your repo in 30 seconds

AI coding assistants happily write hardcoded API keys, disabled TLS verification, and eval() into your codebase — and they never tell you. Run these 4 copy-paste commands in your repo root right now. Each one finds a class of problem that shows up constantly in AI-generated code. A 30-second AI code security sweep — no signup, nothing installed.

The 30-second sweep

1

Leaked API keys and tokens — the classic AI-coding accident:

grep -rnE "sk-[A-Za-z0-9]{20,}|AKIA[0-9A-Z]{16}|ghp_[A-Za-z0-9]{36}|xox[bap]-" . --exclude-dir=.git 2>/dev/null | head -20
Any hits → rotate those keys NOW and move them to environment variables. A committed key is a compromised key.
No hits → good. Still add a pre-commit secret scanner so it stays that way.
2

Hardcoded passwords and credentials in config-shaped code:

grep -rniE "(password|passwd|api[_-]?key|secret)\s*[:=]\s*['\"][^'\"]{4,}['\"]" . --exclude-dir=.git --exclude-dir=node_modules 2>/dev/null | grep -viE "example|placeholder|your-|xxx" | head -20
Any hits → real credentials in source. Move to a secrets manager or env vars; scrub git history.
3

Dangerous dynamic execution — AI assistants love eval() shortcuts:

grep -rnE "\beval\(|\bexec\(|os\.system\(|subprocess\.call\(.*shell=True|yaml\.load\(" . --exclude-dir=.git --exclude-dir=node_modules 2>/dev/null | head -20
Any hits on untrusted input → refactor. eval/exec on dynamic data is a standing invitation for code injection.
4

Disabled security defaults — the "just make it work" leftovers:

grep -rnE "verify\s*=\s*False|_create_unverified_context|StrictHostKeyChecking\s+no|@csrf_exempt" . --exclude-dir=.git --exclude-dir=node_modules 2>/dev/null | head -20
Any hits → each one is a hole an attacker can drive through: MITM-able TLS, unverified SSH, unprotected endpoints.
All four clean → your repo passed the quick sweep. The full scan below goes 50x deeper.

Tip: run these again after every AI-assisted coding session. The patterns above are heuristics — they catch the common cases, not everything.

If you found hits, do this now

  • Rotate every exposed key and token immediately — assume they're already copied.
  • Scrub history — git filter-repo or BFG to remove secrets from past commits.
  • Move secrets to env vars and add a pre-commit hook (e.g. gitleaks) so it can't happen again.
  • Review the AI's diffs — the commands above are a triage pass, not a full audit.

Frequently asked questions

How do I scan AI-generated code for vulnerabilities?

Run a static-analysis (SAST) scanner over the repo — open-source options include Semgrep and vibe-code-focused AI code security scanners — plus a secrets scan for hardcoded API keys, then a dynamic (DAST) scan against the running app. No scanner replaces a human review of authentication, data handling, and business logic.

What is vibe coding security?

Vibe coding security is the practice of checking AI-generated code for the flaws models commonly introduce: hardcoded secrets, injection flaws, cross-site scripting, disabled TLS verification, and insecure defaults. Research (Veracode's 2025 GenAI Code Security Report) found 45% of AI-generated code shipped a real vulnerability.

What are the best AI code security scanners?

Open-source AI code security scanners include vibescan, isitsecure, and AXguard, plus Cloudflare's security-audit-skill and general tools like Semgrep for static analysis and OWASP ZAP for dynamic testing. The right pick depends on your stack: SAST for code, DAST for running apps, secrets scanners for leaked keys.
