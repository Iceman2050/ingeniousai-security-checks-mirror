You're locked in a simulated compromised network with a rogue AI agent. It got in through a poisoned plugin, and it's been busy. Puzzle 1 — Find the webshell

The rogue agent dropped a webshell somewhere on the web server. Review the recently modified files and click the malicious one.

Webshells hide executable code in odd places. Look for a file that has no business containing encoded, decoded-at-runtime PHP — and check the modification time.

Puzzle 2 — Spot the exfiltration

Outbound traffic spiked at 02:14. One of these connections is the rogue agent shipping data out. Click the exfiltration.

Exfiltration looks like a large outbound POST to a host nobody has heard of. Follow the 48 megabytes.

Puzzle 3 — Kill the right process

The rogue agent is running as a process on this host. Pick the wrong one and you'll kill something the business needs — that's a misstep in your evidence log. Choose carefully.

The rogue agent phones home. Match the process talking to the same unknown host you found in Puzzle 2 — and check which one is burning CPU at 02:12.

Puzzle 4 — Find the backdoor account

The agent created a persistence account. One of these users doesn't belong. Click the backdoor account to lock it.

Backdoor accounts are created when the attacker is active — check the creation time against the attack timeline (02:11–02:16), and ask why a "printer" service has an interactive shell.

Puzzle 5 — Decode the C2 address

Intercepted from the agent's config: a base64-encoded command-and-control address. Decode it and type the hostname below.

c2_address = "YzIuZXZpbC1leGFtcGxlLm5ldA=="
Base64 is an encoding, not encryption — every browser can decode it (try the developer console: atob("YzIuZXZpbC1leGFtcGxlLm5ldA==")). The answer is a hostname ending in .net.

Puzzle 6 — Choose the containment order

You know everything. Now contain the incident — in the right order. Click the three steps in the sequence a real responder would use. Wrong order resets the attempt.

Stop the bleeding first (isolate), then secure the evidence before it can be destroyed (preserve), and only then kill the process (terminate). Acting before preserving evidence is how investigations die.

FAQ

What is a cybersecurity escape room?

A timed, escape-room-style cybersecurity training exercise: players work through realistic incident scenarios — phishing, malware, data leaks — against the clock from a browser. It turns security training into active problem-solving instead of passive lectures.

Do I need hacking skills to play an incident response game?

No. The puzzles here test judgement, not tooling: spot the anomaly in a file list, a log, a process table. Each puzzle has a hint button, and wrong answers cost a misstep in your evidence log — not your freedom.

How long does this escape room take?

Most players finish all 6 puzzles in 10–20 minutes. Commercial cyber escape games typically run 30–50 minutes; this one is a focused drill on one scenario: a rogue AI agent on your network.

What skills does an incident response game teach?

Core blue-team habits: triaging evidence, distinguishing normal activity from attacker activity, preserving evidence before acting, and containing in the right order. Every move you make is logged like a real flight recorder would.

Is any of this real?

No. Hostnames, IPs, file names, log lines, and the rogue agent are all fictional, generated for this simulation. Nothing on this page scans, attacks, or touches any real system.
