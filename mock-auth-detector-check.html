Frequently asked questions

What is mock authentication?

Mock authentication is placeholder auth code written for demos, tests or local development — a get_user function that returns a fixed user (often an admin) without verifying any credential, token or signature. It is safe only while it never reaches production. When it ships, anyone who can reach the app is effectively logged in as that user.

What happened in CVE-2026-77932?

Per TheHackerWire's vulnerability entry (Oct 20, 2026), DB-GPT versions up to 0.8.2 shipped a mock get_user_from_headers implementation that granted admin privileges without real authentication, enabling unauthenticated remote code execution. The lesson generalizes: a single leftover mock auth function can hand an attacker the highest privilege in the app with no password at all.

What does this mock-auth detector check?

Paste Python auth code and the in-browser pattern engine flags, with line numbers and severity: mock, demo, fake or stub get_user functions; hardcoded admin or role returns; debug-flag auth bypasses; always-true checks such as if True or return True in a verifier; hardcoded credential comparisons; auth functions that perform no verification at all; and TODO or FIXME auth stubs.

Is it safe to paste my code here?

This page runs entirely in your browser — there is no server, no upload and no storage, and the checker works offline once loaded. Even so, good practice is to paste only the auth function you are reviewing, and to strip real secrets, tokens and production credentials before pasting code into any tool, including this one.

What are the limits of this check?

Honest scope: this is a quick heuristic pattern check in the browser, not a proof your auth is safe. It can miss renamed functions, indirect bypasses and logic flaws, and a clean result is not a security guarantee. The mock-auth-sniffer CLI does the deep AST scan — parsing the code structure, tracing return paths and checking call sites — which catches what text patterns cannot.

How do I fix mock auth before production?

Delete the mock implementation rather than disabling it with a flag; verify a real credential on every request (signed token or session, checked against a secret from the environment); load the user and their role from your user store, never from a literal in the code; fail closed with a 401 on any verification error; and add a startup check that refuses to boot if any bypass flag or demo user is present.
