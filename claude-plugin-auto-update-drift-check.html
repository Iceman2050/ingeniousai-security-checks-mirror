Why auto-update defaults change the threat model

  • Review is a snapshot; updates are a stream. Even if the portal reviewed version 1.0, version 1.3 arrives under the same trust you granted 1.0. Auto-update makes trust perpetual by default.
  • Plugins are bundles, not files. A plugin ships commands, skills, prompts, and MCP servers. One "plugin" is several attack surfaces wearing one name.
  • Maintainer accounts get compromised. The classic supply-chain attack isn't writing malware from scratch — it's pushing it through a trusted maintainer's account. Auto-update delivers it to you overnight.
  • Permissions compound. Your agent's file and network access flows into every plugin and bundled server. One drifted plugin inherits your most trusted context.
  • Detection beats prevention here. You won't review every update — but you can hash plugin directories, watch changelogs, and pin versions for anything with sensitive permissions.

What this check does NOT do

  • It does not scan your plugin directories or verify any plugin's code — it's a provenance self-audit; the inspection is on you.
  • It does not certify any plugin as safe — even official plugins can have bugs or be compromised later.
  • It is not a substitute for sandboxing Claude Code or restricting the agent's own permissions.

Frequently asked questions

Are Claude Code plugins safe?

Mostly — but "plugin" is not a single trust level. Official plugins from Anthropic's portal get more review than sideloaded ones, and since September 25, 2026 the plugin portal has shipped with auto-update defaults ON, meaning plugin code can change under you without a prompt. Safety depends on provenance (official vs sideloaded), whether updates are pinned or reviewed, what bundled MCP servers a plugin includes, and what permissions the plugin's tools hold.

What is the Claude Code plugin portal?

The plugin portal is Anthropic's distribution channel for Claude Code plugins, opened on September 25, 2026. It lets developers publish and users install plugins — bundles of commands, skills, and MCP servers that extend Claude Code. Plugins can be installed from the official portal or sideloaded from other sources, and auto-updates default to ON.

Can Claude Code plugins auto-update?

Yes. Since the plugin portal opened on September 25, 2026, auto-update has been the default — plugin code, commands, and bundled MCP servers can be replaced with newer versions without asking you first. That is convenient, and it is also a supply-chain attack surface: whoever controls the update controls the code your agent runs.

How do I audit Claude Code plugins?

List every installed plugin and its source (official portal vs sideloaded); check whether auto-update is on or pinned; inspect each plugin's declared tools and permissions; enumerate any MCP servers bundled inside plugins; and review update history — would you notice if a plugin's code changed last night? Re-audit whenever a plugin updates or you install a new one.

What is plugin drift risk?

Plugin drift is the gap between the plugin you installed and the plugin running today. With auto-updates on, code, prompts, and bundled MCP servers can change between sessions — including changes pushed after the maintainer's account was compromised. Drift risk is highest for sideloaded plugins with auto-update enabled and no integrity verification.

Do Claude Code plugins include MCP servers?

They can. Plugins are bundles that may include MCP (Model Context Protocol) servers giving the agent tools over your files, network, and apps. A plugin's trustworthiness is therefore the combined trust of its own code plus every bundled server — each server is an independent attack surface with its own permissions.
