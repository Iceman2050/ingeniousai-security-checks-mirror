What should you do when an OpenAI model is retired?

First, inventory every place your code calls the retired model ID — backends, plugins, scripts, and low-code automations. Then map each ID to the vendor-recommended replacement and replay your own production samples before switching, since generations behave differently. Fine-tunes die with their base model and must be retrained. This page checks your stack against the schedule.

Frequently asked questions

Which OpenAI models are being retired?

On October 23, 2026, OpenAI shut down API access to gpt-4-0613, gpt-4-turbo, gpt-4o-2024-05-13, gpt-4.1-nano, gpt-3.5-turbo-0125, gpt-image-1, o1, o1-pro, o3-mini, o4-mini, and fine-tuned models built on those bases, per OpenAI’s deprecations page. The next wave lands January 14, 2027 (gpt-4o, gpt-4o-mini, gpt-4.1 snapshots).

What happens when a model you use is deprecated?

On the shutdown date, API requests to that model ID start failing. In a queue or cron job that can look like silence until somebody notices the backlog. Fine-tunes die with their base model — they must be retrained on a supported base.

What replaces the retired OpenAI models?

OpenAI’s deprecations page recommends gpt-5.6-sol for the gpt-4 family, o1, o1-pro, o3-mini and gpt-4o-2024-05-13; gpt-5.6-terra for o4-mini and gpt-3.5-turbo; gpt-5.6-luna for gpt-4.1-nano; and gpt-image-2.5-sunburst or flare for gpt-image-1. Always replay your own production samples before switching.

How is the migration cost estimate calculated?

It is a transparent, illustrative formula shown on the page: a base migration effort per retired model (12 engineering hours at an illustrative $75/hr) plus a per-million-token regression-testing factor, plus a planning allowance for at-risk models. It is a planning number, not a quote.
