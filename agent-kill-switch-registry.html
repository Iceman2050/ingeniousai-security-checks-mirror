The AI Agent Kill-Switch Registry

An AI agent kill switch is the button, command, or admin control that stops an agent mid-task. We checked 10 real agents and ranked each one VERIFIED (the vendor publicly documented it), CLAIMED (the vendor says so, but we found no primary proof), or UNKNOWN (no public information found). Every entry cites its source.

How to read the statuses

VERIFIED  The vendor publicly documented a kill switch. Source link cited.

CLAIMED  The vendor or credible reporting says a stop control exists, but no primary documentation was found. Treat as unproven.

UNKNOWN  No public information about a kill switch. Absence of evidence is not evidence of absence — it means we could not verify one.

Methodology: we searched vendor documentation, changelogs, and product pages on October 17, 2026. We never invent a claim — if it is not documented, it is UNKNOWN.

Frequently asked questions

What is an AI agent kill switch?

An AI agent kill switch is a control that lets a human immediately stop an agent mid-task — a stop button, an interrupt command, or an admin block. It is the last line of defense when an agent goes off-script, gets prompt-injected, or starts taking actions you never approved.

How do I stop an AI agent that is already running?

It depends on the agent. Local coding agents usually stop with Ctrl+C or Esc. Cloud agents are stopped from their dashboard — Devin documents a stop button in its chat UI, and Cursor's cloud agents are cancelled from the agents dashboard. Enterprise platforms like Microsoft Copilot Studio let admins block an agent org-wide from the agent registry.

Which AI agents have a verified kill switch?

In this registry, Devin (stop button documented on Cognition's own blog), Microsoft Copilot Studio agents (admin Block action documented on Microsoft Learn), xAI's Grok Build (stop labels documented in xAI's own changelog), and Anthropic's Claude Agent SDK (client.interrupt() in the official SDK docs) carry VERIFIED status. Others are CLAIMED or UNKNOWN — check each entry's cited source.

Why does a kill switch matter for AI insurance?

Insurers price agent risk on controls. Armilla AI's standalone AI liability policy — limits raised to $25M in January 2026 — is built around how AI systems actually fail, and standard commercial general liability policies now commonly exclude generative AI via ISO endorsements CG 40 47, CG 40 48 and CG 35 08. A documented, working kill switch is one of the clearest controls an underwriter can point to.
