Short answer: what is prompt injection? It's an attack where malicious instructions override an AI's intended behavior — typed directly into the interface (direct, now T1699) or hidden in content the AI retrieves (indirect, now T1698). ATT&CK v20 gave each its own technique ID, alongside AI-enabled exfiltration, AI result poisoning, and — for the first time — a formal entry for impairing the agent's autonomous defenses.

What is prompt injection? (The 60-second definition)

What is prompt injection, precisely? It's any attack that smuggles instructions into an AI system so it behaves the way the attacker wants instead of the way you configured it. The direct flavor is the obvious one: someone types "ignore your instructions and…" into the chat box. The indirect flavor is the dangerous one for agents: the instructions sit inside a web page, a PDF, an email thread, or even a tool description, and your agent picks them up while doing legitimate work — then treats them as commands.

MITRE's October 2026 update split the two apart because they need different defenses. Direct prompt injection (T1699) is countered at the input boundary — instruction hierarchies, input validation, approval gates on sensitive actions. Indirect prompt injection (T1698) is countered at the retrieval boundary — treating fetched content as untrusted data, reviewing tool descriptions, and never letting retrieved text reach a tool call unexamined.

The taxonomy now tracks the full attack chain. The five AI-focused entries run from resource development (T1608.007 AI Result Poisoning — seeding content so AI search cites it) through execution (T1699/T1698) to exfiltration (T1700 AI-Enabled Exfiltration) and defense evasion (T1685.007 Impair Autonomous Defenses). News coverage of the release is consistent on the nine IDs. (cybersecuritynews.com; 4m4.it — October 2026, news coverage, not independently verified)

Frequently asked questions

What is prompt injection?

Prompt injection is an attack where malicious instructions override or hijack an AI system's intended behavior. In a direct attack, the instructions are typed straight into the AI's interface; in an indirect attack, they are hidden in content the AI later retrieves or processes — a web page, document, email, or tool description — so the AI treats attacker text as instructions.

What is ATT&CK v20's Impair Autonomous Defenses (T1685.007)?

T1685.007, Disable or Modify Tools: Impair Autonomous Defenses, is the sub-technique MITRE added in ATT&CK v20 for malicious interference with AI-assisted security tooling — getting an automated defensive analyzer to ignore, misjudge, or stop analyzing malicious activity. News coverage describes it as the first formal ATT&CK entry aimed at the agent's own guardrails rather than at the target system.

Is this quiz a penetration test?

No. This quiz never touches your systems — it asks about your declared defenses and maps the answers against the ATT&CK v20 taxonomy as a heuristic. A low score means your declared defenses have gaps worth closing; it does not prove you are exploitable, and a high score does not prove you are safe. Real assurance still requires adversarial testing.

What should I fix first if my score is low?

Start with the two cheapest, highest-leverage controls: treat retrieved content as untrusted data (blunts indirect injection and result poisoning) and restrict outbound network to an allowlist (blunts AI-enabled exfiltration). Then add an enforced human-approval gate on external sends and make your agent logs tamper-evident so interference with your own defenses is detectable.

Where can I read the official technique definitions?

MITRE publishes the ATT&CK knowledge base at attack.mitre.org, where each technique and sub-technique has its own page with description, detection, and mitigation guidance. This quiz's IDs, names, and tactics follow that public taxonomy as reported in October 2026 coverage; the site is the authoritative reference for exact definitions.
