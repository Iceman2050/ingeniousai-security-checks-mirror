Claude Code "SneakPeek" — poisoned HTML steals dev secrets via preview pane

Noma Labs disclosed SneakPeek (CVSS 8.7) in Claude Code Desktop: a poisoned HTML file over 256KB in any cloned repo — a test coverage report is the classic lure — gets auto-rendered by the preview pane as a file:// URL with no CSP, letting embedded JavaScript silently read SSH keys, AWS credentials, GitHub tokens and Kubernetes configs and exfiltrate them. No click required. Anthropic's first patch was bypassed via a Web Worker before the full fix shipped in build 1.30096.1 (Aug 17). The pattern — a size-based security boundary with two code paths, one guarded, one not — is one every AI-tooling builder should audit for.

PoeLLM "Canto Incognito" — jailbreak hidden in a poem

The first adversarial-format jailbreak seen in real attacks: malware operators hid their command-and-control instructions inside a poem posted on GitHub, defeating AI safety guardrails that scan for suspicious text. Active since April, it has infected 3,000+ servers by breaking into exposed LiteLLM and Ollama instances. Anyone self-hosting LLM infrastructure is in the blast radius — and the technique generalizes to every AI deployment.

What is prompt injection and how does it manipulate LLMs?

Prompt injection is an attack that tricks an AI system into following instructions from an untrusted source. It works because LLMs process everything — your request, tool outputs, web pages, files — as one text stream, so the model can mistake attacker-planted text for orders it should obey.

What is the difference between direct and indirect prompt injection?

Direct prompt injection is typed straight at the model by the user — the classic “ignore previous instructions”. Indirect prompt injection hides the instructions in content the model reads on your behalf — a web page, email, document, or file — so the attack arrives through the data channel instead of the chat box.

Can input sanitization completely stop prompt injection?

No. Sanitization and blocklists buy time, but attackers constantly rephrase, encode, or multi-turn their way around filters — OpenAI has acknowledged the underlying problem may never be fully solved. The accepted strategy is defense in depth: least-privilege agents, human approval for irreversible actions, and monitoring.

How does OWASP classify prompt injection?

OWASP ranks prompt injection as LLM01 — the number-one risk for LLM applications in its LLM Top 10, covering both direct and indirect prompt injection. It has held that position for two years running.
