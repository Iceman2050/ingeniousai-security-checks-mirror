IoT security news: what OX Security found

MCP, the Model Context Protocol, is how AI agents reach tools: files, calendars, home devices, media libraries. Enthusiasts run MCP servers at home so their agents can reach real things, then punch a hole for remote access: an ngrok tunnel, a forwarded port, a reverse proxy. Each hole is a door, and doors get indexed. OX Security's scan walked through the ones left open: 15,465 servers answering the public internet.

A home MCP server is not a toy exposure. It can hold the keys to the house in the literal, smart-home sense: device controls, files, messages, sometimes credentials for other services. The owners are rarely careless people; they are early adopters whose tunnel outlived the experiment that needed it.

Why do home AI servers end up public?

Because remote access is the feature everyone wants on day two. The agent should reach the home server from anywhere, so a tunnel goes up, and the tunnel is furniture: invisible, always on, and never revisited when the experiment ends. Scanners do not care why the door is open. They catalogue open doors continuously, and 15,465 MCP servers were in the catalogue.

Get off the exposed list: the working order

  1. Probe yourself first: run HomeShield's read-only probe on your endpoint's public URL. If it answers, you have your answer before any scanner's report does.
  2. Close leftover tunnels: kill every ngrok tunnel and forwarded port you cannot tie to a current need. Experiments end; their doors should too.
  3. Authenticate the endpoint: tunnel auth is not endpoint auth. The MCP server itself should demand a credential you control.
  4. Prefer a VPN over a hole: remote access through a mesh VPN keeps the server off the public internet while keeping it reachable to you.
  5. Inventory monthly: one list: servers, tunnels, forwards, and what each exposes. Five minutes a month is the whole control.

What is an MCP server?

An MCP server is a program that exposes tools and data to AI agents through the Model Context Protocol: files, devices, calendars, media, smart-home controls. Home users run them so their agents can reach real things. HomeShield MCP checks whether such a server, run at home, is reachable from the public internet when it should not be.

How do I know if my home AI server is exposed?

Ask it from the outside: probe the endpoint's public URL as a stranger would. HomeShield automates that with read-only requests. If the endpoint answers and offers its tools without authentication you control, it is exposed. Also inventory your tunnels and port forwards: the exposure is usually a leftover path, not the server itself.

How do I un-expose a home MCP server?

Close the public path first: kill leftover tunnels and forwarded ports. Then put authentication on the endpoint itself, not only on the tunnel. For remote access you still want, use a VPN or mesh network so the server stays off the public internet. Finally, re-probe from the outside to prove the door is shut.
