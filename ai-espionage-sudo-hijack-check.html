LINUX SECURITY — OCT 2026

Spies stole Linux passwords without touching sudo.

Palo Alto Networks Unit 42 reports an espionage campaign — tracked as CL-UNK-1211, active Oct 2025–Apr 2026 against government and state-affiliated Linux infrastructure — that stole credentials by replacing victims' .bashrc with a version containing a malicious sudo alias. The alias intercepted typed passwords, copied them to an attacker log disguised as Solarwinds.StatusLog.txt, and passed everything through to the real sudo. Updating sudo would not have stopped it. Five questions for Linux admins.

Short answer: the attack lives in shell startup files, not in the sudo binary. Monitor .bashrc/.profile integrity, alert on sudo aliases and wrappers, keep EDR tamper-protection on, and audit PHP configs and privilege-escalation CVEs.

How the sudo hijack works (technique, not payload)

  • The plant: attacker replaces the victim's .bashrc with a modified copy containing a malicious alias shadowing sudo.
  • The intercept: every time the victim runs sudo, the alias captures the typed password into an attacker log — then forwards the command to the real sudo, so the session behaves perfectly normally.
  • The camouflage: the stolen-password log was named Solarwinds.StatusLog.txt to blend in. Unit 42 found no evidence SolarWinds was compromised — the name was pure disguise.
  • Why patching fails: the malicious code is in the shell config, not the sudo binary. Reinstalling or updating sudo leaves the alias untouched.
  • The fix: file-integrity monitoring on shell startup files plus a known-good baseline diff — the alias shows up immediately.

The AI angle — what the evidence does and does NOT prove

  • What Unit 42 found: multiple malicious scripts carried conversational, step-by-step reasoning comments — Base64 commands, section headers, switching between PHP, JS, Bash and Python — consistent with LLM output or an automated AI agent. Unit 42's assessment: AI helped create or adapt parts of the toolkit.
  • What it does NOT prove: that AI planned the campaign, chose the targets, or ran the operation. Humans were clearly in the loop.
  • The cautionary detail: one mailbox-exfiltration script (zip_mails.sh) had malformed syntax and would have failed outright — AI assistance did not guarantee working code.
  • Takeaway: AI is becoming a force-multiplier for attackers' tooling, not a replacement for the attacker. Defenders should expect faster, more varied malware — the detection fundamentals (integrity monitoring, EDR, egress control) still apply.

Detect and harden — this week

  • Monitor shell startup files. File-integrity monitoring on ~/.bashrc, ~/.profile, ~/.bash_profile, /etc/profile.d/ — alert on any change outside approved windows.
  • Hunt the alias. Periodically audit for unexpected aliases and wrapper functions shadowing sudo, su, ssh on every host.
  • Keep EDR tamper-protection on. CL-UNK-1211 tried to kill Cortex XDR; the attempts were detected and blocked — tamper protection is what made that possible.
  • Audit PHP configs. Check auto_prepend_file across web servers for anything pointing outside your approved include path.
  • Patch the privesc path. PwnKit (CVE-2021-4034) is years old and still shows up in campaigns — verify it is patched; scan for React2Shell (CVE-2025-55182) exposure.
  • Watch the doors. Review authorized_keys for unknown entries; alert on outbound WebSocket connections to unknown infrastructure.
