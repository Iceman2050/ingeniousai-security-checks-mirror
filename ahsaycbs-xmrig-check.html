Step 2 — Hunt for compromise signs

Patching closes the door; it does not remove intruders already inside. If the server was internet-exposed before the hotfix, check for these attacker artifacts (Huntress + Bitdefender MDR observations):

  • edge.exe or msedge.exe in temp directories — XMRig miners impersonating Microsoft Edge. Real Edge does not live in temp folders.
  • A service named MicrosoftEdgeUpdateSvc — fake Edge updater service used for miner persistence.
  • JSP web shells in the AhsayCBS web application directories — small scripts turning web requests into a command shell.
  • Files staged in C:\Users\Public — writable by every local user; attackers drop tooling here via curl/certutil.
  • Taskgmr.ps1 — AI-assisted PowerShell that kills Windows Task Manager when opened (anti-analysis). Task Manager dying at night is a symptom, not a glitch.
  • Unexpected OpenSSH installation — backdoor that survives patching because it doesn't depend on the vulnerable web service.
  • Suspicious processes spawned by cbssvcX64.exe — the AhsayCBS service process should not be launching miners or shells.
  • New services, scheduled tasks, or elevated accounts you didn't create.
Found any of these? Treat the box as fully compromised: isolate it, preserve forensic images, rotate every credential the server touches, and assume backup data was reachable. Then rebuild from known-good media — don't just patch over an intrusion.

Why this is worse than it looks

  • The "patched" versions weren't. Versions 9.15.2.59 and 10.3.4.0 (August 2026) were assumed fixed; Ahsay later confirmed the patches were incomplete and Huntress showed even 10.3.4 was still exploitable — effectively a zero-day window that lasted two months.
  • Patching does not evict attackers. OpenSSH backdoors, services, and scheduled tasks persist after the hotfix. "Patched and rebooted" without an IOC hunt is a false sense of safety.
  • The miners hide in plain sight. Naming the miner edge.exe and the service MicrosoftEdgeUpdateSvc exploits admin trust in Microsoft-signed-looking names.
  • Anti-analysis is automated now. The Taskgmr.ps1 script — suspected AI-written — watches for Task Manager and kills it. If your monitoring relies on someone noticing a slow server, it will miss this.
  • The clock is real. Exploitation started October 7; CISA's KEV deadline is October 17, 2026. Attackers had a 10-day head start on most defenders.

What to do right now

  • Patch to v10.3.4.45 (v10 branch) or v9.15.2.70 (v7/v8/v9 branches) from Ahsay — downloads need a valid partner account — then reboot the server as Ahsay instructs.
  • Hunt the IOCs in Step 2 before declaring the box clean.
  • Verify your backups are intact and restorable — this is backup infrastructure; confirm backup jobs still run and data wasn't tampered with.
  • Rotate credentials stored on or reachable from the server.
  • Restrict AhsayCBS management ports to trusted IPs/VPN — this attack needed the web service to be reachable.

FAQ

What are CVE-2026-105133 and CVE-2026-105134?

CVE-2026-105133 is an improper authentication vulnerability in AhsayCBS's checkSysPwd() function; CVE-2026-105134 is an OS command injection in the Replication Receiver component (/rps/api/json/UpdateReceivers.do). Attackers chain them to bypass authentication and execute arbitrary OS commands with NT AUTHORITY\SYSTEM privileges — no login required.

Is AhsayCBS 10.3.4 still vulnerable?

Yes. Huntress confirmed that the August 2026 patches (9.15.2.59 and 10.3.4.0) did not fully fix the flaws, and that even the latest listed version 10.3.4 remained exploitable — effectively a zero-day. The complete fixes are the v10.3.4.45 hotfix (v10 branch) and the v9.15.2.70 hotfix (v7/v8/v9 branches), followed by a server reboot.

What do the attackers do after exploiting AhsayCBS?

Per Huntress and Bitdefender MDR: plant JSP web shells in the AhsayCBS web app directories, stage payloads in C:\Users\Public, install XMRig cryptominers disguised as edge.exe / msedge.exe (with a service named MicrosoftEdgeUpdateSvc), drop an AI-assisted PowerShell script (Taskgmr.ps1) that kills Windows Task Manager to hide mining, install OpenSSH for a backdoor, and create services, scheduled tasks, and elevated accounts for persistence.

What is the CISA deadline for the AhsayCBS flaws?

CISA added both flaws to its Known Exploited Vulnerabilities (KEV) catalog, requiring US federal agencies to patch by October 17, 2026. Private organizations should treat the same date as the urgency bar — exploitation began October 7, 2026, and Huntress saw at least five organizations targeted by October 8.

What is a CVE checker?

A CVE checker is a free tool that tells you whether your software is affected by a published CVE — a publicly known cybersecurity vulnerability. It compares your version or configuration against the official advisory and gives you a patched, vulnerable, or unknown verdict in about 30 seconds.

How do I check if my software has a CVE?

Find your exact version number, then compare it against the vendor's security advisory or the NVD entry for the CVE. The fastest way is a CVE checker built for that product: paste your version and get an instant verdict against the published version tables.

How do I know if I am affected by a CVE?

You are affected when you run a vulnerable version and the vulnerable component is reachable or enabled — for example, open sign-ups, an exposed management port, or a vulnerable app installed. A CVE checker gives you the version verdict in seconds; the advisory's conditions tell you whether that verdict means real exposure.
