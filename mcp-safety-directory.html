⚠️ HONEST SCOPE

These ratings reflect one unauthenticated probe run on 2026-10-17 — not a certification. They measure negotiation behavior only: whether a server silently downgraded the newest protocol era. A silent downgrade is not a vulnerability finding, and an "N/A — unobservable" rating is not a finding of wrongdoing (those servers answered every probe with HTTP 401, so independent verification is impossible). Methodology — exactly what was measured

Run date: 2026-10-17. Tool: open-source mcp-negotiation-prober (MIT) — sends an MCP initialize handshake with protocolVersion set to each of 6 eras (2024-11-05, 2025-03-26, 2025-06-18, 2026-07-28, plus fictional 1999-01-01 and 2037-12-31) and classifies the echoed version. No credentials used; every probe was an unauthenticated handshake. Endpoints were taken from vendors' own published docs. An endpoint was included only if it responded at all (including HTTP 401). Verdicts describe negotiation behavior only — results are reproducible: same tool + same endpoints = same verdicts. Full detail: State of MCP Security 2026.

Grades are recomputed every probe run. A vendor that declares its negotiated version publicly — or opens negotiation to unauthenticated verification — moves up on the next run. Downgrades that are declared are not downgrades we can see, and honesty is the only thing graded here.

MCP security FAQ

What are the security risks of MCP servers?

An MCP server can expose powerful tools — file access, code execution, credentials, network calls — to any AI agent connected to it. Key risks include over-permissioned tools, prompt injection through tool descriptions, silent protocol downgrades, and negotiation behavior hidden behind OAuth walls, as our 2026-10-17 probe documented.

How do you audit an MCP server?

Probe its negotiation behavior to check for silent protocol downgrades, review every tool’s permissions and descriptions for injected instructions, verify authentication and scope design, and re-verify after vendor updates. Our open-source mcp-negotiation-prober on GitHub automates the handshake part of that audit.

What is an MCP security checklist?

A minimum checklist: verify the negotiated protocol version per session — not just the requested one — review tool permissions and descriptions, demand version transparency from vendors, pin and log what each tool can touch, and re-run checks after every vendor update. The directory above grades 27 public servers on the first item.
