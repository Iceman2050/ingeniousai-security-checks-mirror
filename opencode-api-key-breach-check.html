OpenCode breached — and your API keys may be paying for the attack.

On Oct 17, 2026, the open-source AI coding platform OpenCode disclosed "unauthorized access to a legacy system" — one that was being decommissioned. Third-party provider keys (OpenAI, Anthropic and others) saved in users' workspaces may have been exposed. OpenCode calls it a "large scale distillation attack" hitting about 1.4% of Console users — those with external providers linked. Attackers weren't after passwords: they used the keys to hammer high-end AI models, and victims watched their balances drain — some into the hundreds of dollars.

Short answer: if you got OpenCode's email, revoke and replace your provider keys now, update every app using them, and audit your usage and billing. If you didn't get the email, OpenCode says you were not impacted. And this is a real-world distillation attack — the exact threat class we cover in our distillation defense check.

What happened (as disclosed)

  • Oct 17, 2026: OpenCode discloses via its X account and individual emails — "unauthorized access to a legacy system" that was being decommissioned; "third party provider keys (eg OpenAI, Anthropic) saved in your workspace may have been exposed."
  • Scale: about 1.4% of OpenCode Console users — specifically those with external providers linked.
  • OpenCode's framing: a "large scale distillation attack" — stolen keys used to run repeated queries against high-end models.
  • Impact: victims' provider balances drained, some bills reaching into the hundreds of dollars.
  • Remediation: OpenCode says it is working with Anthropic, OpenAI, and Google; no further technical details, and the incident is described as ongoing.
  • Who was affected: per OpenCode, if you did NOT receive the email, you were not impacted.
  • Latest (Oct 17, community reaction): developers are treating this as a self-custody wake-up call — "not your keys, not your tokens": keys parked in a third-party console are only as safe as that console. Affected users are also asking who pays for the drained balances; as of this writing there is no official answer yet from OpenCode or the providers.

Sources: OpenCode's X disclosure and user email notices, as reported by wpnews.pro and 7minai.com. Claims attributed as stated by OpenCode; details are thin while the incident is ongoing.

What to do NOW

  • 1. Revoke the keys. In each provider's dashboard (OpenAI Platform → API keys, Anthropic Console → API keys, Google AI Studio), revoke every key that was ever saved in an OpenCode workspace.
  • 2. Issue fresh keys. Create replacements and update every app, script, and CI job that used the old ones — a revoked key left in a config breaks the app; a live key left in a config breaks your budget.
  • 3. Audit usage and billing. Review recent usage for spikes you don't recognize — unexpected model calls or regions are the fingerprint of key abuse.
  • 4. Set billing alerts. Hard caps and spend alerts turn the next key compromise into a notification instead of a surprise bill.
  • 5. Scope keys least-privilege. Separate keys per project, restricted to the models and endpoints each project actually needs.

The bigger lesson

  • Your bill is an attack surface. AI coding tools sit between you and paid APIs — a key compromise is both a security incident and a surprise invoice. This is the first major breach where the theft was the compute.
  • Decommissioned systems are classic weak points. The breached system was legacy and on its way out — exactly the infrastructure teams stop patching and watching.
