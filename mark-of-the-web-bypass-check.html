Why is the Mark of the Web bypass in cybersecurity news?

Windows tags downloaded files with the Mark of the Web, triggering SmartScreen warnings and blocking macros. Attackers bypass it with ISO, VHD, and archive tricks so payloads run silently. When the tag is stripped, your first line of download defense is gone — and most users never notice. This check shows whether your files still carry the mark and what a missing tag means.

How to check a file's Mark of the Web

Method 1 — right-click, 10 seconds

Right-click the file → Properties. If you see a Security line reading "This file came from another computer and might be blocked to help protect this computer" with an Unblock checkbox, the Mark of the Web is attached. No Security line at all? The file carries no tag.

Method 2 — PowerShell, the ground truth

Open PowerShell and run:

Get-Item -Path "C:\path\to\file.exe" -Stream Zone.Identifier

If it prints a block containing ZoneId=3, the file is tagged as from the Internet. If it errors or prints nothing, no Mark of the Web exists on that file. To see the raw tag:

Get-Content -Path ".\file.exe" -Stream Zone.Identifier -Raw

What the ZoneId numbers mean

ValueMeaning
ZoneId=0My Computer — created locally
ZoneId=1Local intranet
ZoneId=2Trusted sites
ZoneId=3Internet — downloaded from the web
ZoneId=4Restricted sites

Note: the tag lives in an NTFS alternate data stream, so it only survives on NTFS drives. Copying a file to a FAT32 USB stick, or extracting it with some third-party archivers, can strip it without any attacker involved — which is why a missing tag is a warning flag, not proof of attack.

What it means if the tag is missing

  • Benign: the file passed through a tool or drive that doesn't preserve alternate data streams (some archivers, non-NTFS drives, certain sync tools).
  • Suspicious: someone deliberately cleared it with Unblock-File — legitimate if they verified the source, dangerous if you don't know who did it.
  • Dangerous: on a system missing the October 2026 update, the CVE-2026-96951 bypass silently delivered internet files with no tag at all. A fresh download with no Zone.Identifier on an unpatched machine is exactly what this attack looks like.

Absence of MotW never proves a file is safe. Presence of MotW never proves a file is dangerous. It is one signal — and this CVE turned off the signal.

Hardening checklist — do these now

Install the October 2026 cumulative update. Settings → Windows Update → Check for updates. This is the one that closes CVE-2026-96951. Verify in PowerShell: Get-HotFix | Sort-Object InstalledOn -Descending | Select-Object -First 5
Turn SmartScreen fully on. Settings → Privacy & security → Windows Security → App & browser control → Reputation-based protection — every toggle ON.
Keep Office Protected View on for internet files. In any Office app: File → Options → Trust Center → Trust Center Settings → Protected View — all three boxes checked.
Never Unblock blindly. The Unblock checkbox and Unblock-File remove the tag permanently. Only clear it after you personally verified who sent the file and why.
Treat unexpected downloads as hostile. An attachment you didn't ask for is a suspect until proven otherwise — on a vulnerable system it needed no click-through warning to hurt you.

Ticking the boxes is local to this page (nothing is uploaded anywhere). Missed one? Do it, then re-take the check above.

Frequently asked questions — FAQ

What is Mark of the Web?

Mark of the Web (MotW) is a Zone.Identifier alternate data stream that Windows NTFS attaches to files downloaded from the internet or received from untrusted sources. When MotW is present, Windows applies extra caution: Microsoft Defender SmartScreen warnings, Office Protected View for documents, and Smart App Control blocks. Think of it as the 'from the internet' sticker every guard in the building checks.

How do I check if a file has Mark of the Web?

Right-click the file, choose Properties, and look for a Security line reading 'This file came from another computer and might be blocked' with an Unblock checkbox — that means MotW is attached. Or in PowerShell run: Get-Item -Path 'C:\path\to\file.exe' -Stream Zone.Identifier. Output containing ZoneId=3 (Internet) means the tag is present; no output means the file carries no MotW.

What does it mean if a downloaded file has no Mark of the Web?

Three possibilities. Benign: some extraction tools and transfer methods strip the alternate data stream. Suspicious: someone deliberately removed it with Unblock-File. Dangerous: on an unpatched system, the CVE-2026-96951 bypass silently delivered the file with no tag. If a file you just downloaded from the internet shows no Zone.Identifier, treat it as hostile until verified — and make sure the October 2026 update is installed.

How do I remove the Mark of the Web from a file?

Right-click the file, choose Properties, and tick the Unblock checkbox at the bottom — this permanently removes the Zone.Identifier tag. In PowerShell, run Unblock-File -Path 'C:\path\to\file'. Only remove the tag from files you personally verified as safe: unblocking also removes SmartScreen and Protected View coverage for that file.

Am I safe if I installed the October 2026 update?

The October 2026 cumulative update closes the bypass on your machine, so MotW enforcement works normally again. You still need the hygiene: SmartScreen on, Office Protected View on, and never Unblock a file you weren't expecting. The bypass needs a vulnerable Shell to fire, so a patched system is not affected by it.
