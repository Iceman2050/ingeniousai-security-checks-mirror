Agentic AI: signed mandates set the standard

Google's AP2, the Agent Payments Protocol, builds authorization into the transaction itself: signed mandates that state what the agent may do, traveling with the payment. Why do agent actions need receipts when human actions do not?

Because human actions carry their context with them: a person at a keyboard, in a session, inside working hours, able to explain themselves afterwards. An agent action has none of that. It is an API call at 3 a.m. by a system that cannot be interviewed. The receipt is the context, recorded at the only moment it exists.

Audit your agent evidence trail: pick one action, prove it

Think of the most consequential action any of your agents took last month. Everything runs in your browser; nothing is sent anywhere.

Give every agent action a receipt: the build order

  1. Define consequential: list the agent actions that need approval evidence: payments, external messages, record changes, access grants. Everything else can stay light.
  2. Record at the moment: the receipt is created when the approval happens, binding approver, action, agent and time. Backfilled records are claims, not receipts.
  3. Chain the records: hash each receipt to the previous one, so the trail is append-only in practice and any edit breaks the chain visibly.
  4. Name the agent: distinct identity per agent, recorded on every receipt. Shared accounts make every agent responsible for every action.
  5. Rehearse the export: produce the evidence pack for one real action and time it. Agentic Receipts makes the pack a single export.

Frequently asked questions

What is an agentic AI receipt?

An agentic AI receipt is a tamper-evident record of an approval: who approved what, for which agent, at which time. Agentic Receipts chains receipts with SHA-256 hashes, so each record links to the one before it and any edit breaks the chain. The result is evidence an operator can export when an agent's action is questioned.

What is agentic AI?

Agentic AI is AI that acts: systems that pursue goals through tools, APIs and other software with limited human supervision, rather than only answering questions. The category's search demand is large and growing: 'agentic AI' drew about 101,000 US searches a month in 2026 (Ahrefs). The more these systems act, the more their operators need evidence of what was authorized.

How do receipts relate to Google AP2 and the card networks?

AP2 and the card networks' intent systems carry authorization inside their own payment rails. Agentic Receipts is the operator-side layer: receipts for any consequential agent action, payments included, held in your own systems across vendors and rails. The standards are converging on the same principle from different sides.

Which agent actions need receipts?

Any action that would be awkward to explain without one: payments and purchases, messages sent to customers, changes to records, grants of access, deletions. Low-stakes reads and drafts can stay light. The rule of thumb: if the action would appear in a dispute, a review or a regulator's question, it needs a receipt.

Can receipts be created after the fact?

A record written after the fact is a statement, not a receipt: it asserts an approval rather than proving one was recorded when it happened. Receipts earn their credibility from timing and tamper-evidence. Build the habit at approval time; the trail compounds in value with every undisputed action it covers.
