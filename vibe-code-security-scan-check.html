SAST vs DAST in 30 seconds — and why scanners cry wolf

  • SAST (static): reads your source code without running it. Catches SQL concatenation, hardcoded secrets, dangerous functions — fast, early, but noisy.
  • DAST (dynamic): attacks the running app like an outsider. Catches auth bypasses, runtime misconfigurations — real proof, but only after the app runs.
  • Together: they cover each other's blind spots. The ScanHub alpha's whole pitch is this combo, purpose-built for vibe-coded apps.
  • The false-positive problem: scanners flag plenty that isn't exploitable. Teams that don't triage findings stop reading reports — and the real vulnerabilities hide in the ignored pile. That's why the demo plugs AI in as the reviewer: to separate signal from noise before a human signs off.
The 4 flaw classes the demo caught — check yours for each:
• SQL injection via string concatenation → use parameterized queries or an ORM.
• Arbitrary code execution via eval() on dynamic input → ban eval(); never execute user input.
• Secrets in source code (incl. a Stripe publishable key) → env vars + secret scanning in CI.
• XSS via innerHTML assignment → render untrusted content as text, never HTML.
