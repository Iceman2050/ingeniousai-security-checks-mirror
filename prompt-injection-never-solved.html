The 6-layer defense playbook

Each layer assumes the previous one failed. Implement in order — layer 1 is the mindset shift everything else rests on.

1. Assume breach at the prompt layer

Treat every model output as untrusted input — the same way you'd treat user input in a web app. The injection is not a bug you patch; it's a permanent property of the environment.

Do today: find one place where model text flows straight into a shell command, SQL query, or API call — and put an allowlist or validation boundary between them.

2. Least-privilege agents

An agent with shell, file-write, and network tools is a loaded weapon. Most agents are deployed with far more capability than their job requires.

Do today: audit your agent's tool list and revoke everything it doesn't strictly need. No shell access for a summarizer. No credential scope for a search agent.

3. Human-in-the-loop for sensitive actions

Anything irreversible — payments, deletions, external messages, permission changes — needs a human yes, every time. This is the backstop that catches what layers 1–2 miss.

Do today: add an explicit approval gate before your agent's highest-impact action. One confirmation dialog is cheaper than one incident.

4. Output validation

Don't trust the shape of what the model returns. Schema-check, sanitize, and reject anything that doesn't validate before acting on it.

Do today: enforce a JSON schema on one agent output and drop (with a logged alert) anything that fails validation.

5. Monitoring + canaries

You can't prevent every injection — so detect it. Plant canary tokens in your data and RAG corpus; when a model repeats one back, you have proof of manipulation or leakage.

Do today: plant your first canary and set up an alert for it — the free prompt-injection-canary project implements the pattern.

6. Lockdown-Mode-style restrictions

Constrain the agent's operating envelope the way OpenAI's Lockdown Mode does: sandbox it, strip direct internet and credential access, route sensitive operations through a narrow reviewed API.

Do today: run your highest-risk agent in a sandbox with no direct credential access — even a read-only filesystem + proxied network is a massive improvement.

Why "unsolvable" is the honest framing

  • What's proven: per the MultiBreak benchmark, multi-turn attacks succeed ~99% of the time against major models — one turn plants a false premise, later turns build on it, and no single turn looks malicious in isolation. Data poisoning compounds it: tamper with a RAG corpus or training data and the model carries compromised knowledge into every future interaction, no prompt needed at inference time.
  • What's NOT proven: that any vendor has a complete fix. OpenAI's own admission — plus a Lockdown Mode that contains rather than cures — is the industry's most honest signal yet. Only about one-third of organizations have deployed dedicated defenses at all.
  • The real near-term risk isn't a superintelligent jailbreak — it's ordinary agents with excessive permissions executing injected instructions against real systems: the McKinsey Lilli incident earlier this year showed how fast an autonomous agent can turn prompt techniques into data exposure.
  • The takeaway: stop budgeting for a patch that ends the problem. Budget for layers — each one cheap, each one catching what the last missed.
