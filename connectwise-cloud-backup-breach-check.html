ACTIVE SUPPLY-CHAIN ATTACK — REPORTED OCT 16–17, 2026

A backup app's stolen credential walked into 173 Microsoft 365 tenants — was yours one of them?

Huntress caught unknown attackers using a compromised credential belonging to ConnectWise Cloud Backup (formerly SkyKick) to obtain Microsoft Graph tokens across 173 customer and partner tenants. No passwords cracked, no MFA prompt — they signed in as the trusted backup app itself and inherited its permissions: mailboxes, OneDrive, SharePoint, Teams, directory data. Five questions, 60 seconds, to check your exposure.

Short answer: if ConnectWise Cloud Backup (AppId 506e08f9-6e9a-4da4-942b-a099a03644ae) is consented in your tenant, you are in the affected population — the stolen credential works everywhere the app was authorized. The attack ran October 15, 06:13–08:34 UTC from 144.172.64.128, tenants hit in sorted GUID order seconds apart (a script, not a human). Microsoft tracks it as an active supply-chain attack. What actually happened (verified)

Oct 13–14: the same IP (144.172.64.128, a hosting-provider address) password-sprayed four law-firm tenants. No successful user sign-ins detected in Huntress telemetry — a warm-up.
Oct 15, 06:13–08:34 UTC: the actor authenticated as the ConnectWise Cloud Backup app using its stolen vendor credential and pulled Microsoft Graph tokens across 173 partner/customer tenants, moving through tenant IDs in sorted GUID order, seconds apart — an automated target list.
Escalation: in at least one tenant the app granted itself Global Administrator and added new client secrets to other trusted applications — including an MSP management app and a security platform — building persistence beyond the stolen credential.
Response: ConnectWise closed access to the Cloud Backup app and says it has no evidence of partner backup data compromise. Microsoft Threat Intelligence is tracking it as an active supply-chain attack on the app's OAuth identity.

Why this one is nasty

  • No user login, no MFA: the login records show a client assertion — the secret came from the vendor's home tenant, not from anything inside yours. App-only identities never see an MFA prompt.
  • Consent is the key: every permission your tenant already granted the backup app became the attacker's permission. 173 tenants confirmed — the true number is "everywhere the app is installed."
  • Absence of evidence isn't evidence: Huntress warns that a lack of visible mail or file access in logs does not prove nothing was taken — directory reads via Graph leave thinner audit trails.

Sources: The Hacker News · SparTech · CyberSecurityNews · Capstone (reporting by Huntress; Microsoft Threat Intelligence tracking)

Do this today if you're in the affected population

  • Search sign-in logs for AppId 506e08f9-6e9a-4da4-942b-a099a03644ae and for auth from 144.172.64.128 since Oct 15.
  • Audit service principals: any new client secrets or credentials added in the last 30 days that nobody on your team recognizes?
  • Review app consent: does ConnectWise Cloud Backup still hold Global Admin or Directory.ReadWrite.All? Remove what you don't actively use.
  • Watch for persistence: new service principals, new app registrations, or consent grants appearing after Oct 15 are red flags.
