FAQ

What permissions should an AI agent have?

Only what its task genuinely needs — this is the least-privilege principle. Define the exact tools, data sources, and actions (read vs. write vs. send vs. delete) per task, start at read-only, and add broader access one deliberate step at a time. Never hand an agent blanket admin scopes "just in case."

Should an AI agent have its own identity?

Yes. Give every agent a distinct service identity instead of letting it inherit a human's credentials, and name one human owner accountable for what it does. If the policy lives where the agent can rewrite it, it is a suggestion — enforcement must sit outside the agent.

How do you revoke an AI agent's access?

Run the kill switch in this order: revoke its API keys and tokens, disable its tool grants at the authorization layer, export the session logs for forensics, then verify no new tool calls occur after revocation. Use short-lived credentials so access expires on its own even if you forget.

Who is responsible when an AI agent causes harm?

The named human owner. Governance guidance is consistent on this: every agent needs an accountable individual who approved its permissions and scope before deployment. Document that ownership in the prenup — ambiguity is what makes incident response slow.
